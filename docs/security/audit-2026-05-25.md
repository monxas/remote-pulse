## Executive Summary

Pre-release security review for Remote-Pulse v0.1.0 agent and server. Focus: secrets scanning, static analysis, dependency vulnerabilities, defense-in-depth validation.

**Key findings:**
- ✅ 0 verified secrets in repository (trufflehog clean)
- ✅ Audit log immutability enforced (Postgres triggers)
- ✅ Defense-in-depth layers validated (Tailscale identity + JWT + local-approval + Telegram)
- ✅ Security headers implemented (HSTS, CSP, X-Frame-Options, etc.)
- ⚠️ Rate limiting at Caddy level (application-level fallback deferred to v0.2)
- ⚠️ Code signing budget deferred (Windows EV cert ~$300/yr, targeting v0.2.0)

## 1. Scope

**In scope:**
- Agent: `/agent/src`, install scripts (`scripts/install.sh`, `scripts/install.ps1`)

### 3.4 Authentication & Authorization

#### Multi-layer auth validated:

1. **Tailscale identity (Layer 1)**
   - Injected by `tailscale serve` reverse proxy as `Tailscale-User-Login` header
   - Not spoofable (Tailscale validates via WireGuard keypair)
   - Enforced: Server rejects requests without valid header

2. **JWT enrollment tokens (Layer 2)**
   - Single-use, 24h TTL, 256-bit random (HS512)
   - Bound to host fingerprint at first use
   - Rotation procedure: `scripts/rotate-jwt-secret.sh` (invalidates all pending tokens)

3. **Local-approval enforcement (Layer 3 — agent-side)**
   - Agent checks `/etc/rp/allow-remote-exec` before executing destructive commands
   - Defense-in-depth: Mitigates server compromise → full fleet escalation
   - Validated in agent source: `src/rp_agent/executor.py`

4. **Telegram approval (Layer 4 — human-in-the-loop for prod/iarq)**
   - Destructive ops in sensitive groups require n8n Telegram approval
   - Server-side check: `routers/approvals.py`

#### Test coverage:
- Enrollment flow: `test_enroll.py` (JWT validation, replay protection)
- Tailscale identity: `test_tailscale_identity.py` (header injection)
- Command signing: `test_signing.py` (Ed25519 signature verification)
- Audit log: `test_audit_log_immutability.py` (Postgres trigger enforcement)

### 3.5 Audit Log Immutability

**Status:** ✅ VALIDATED

**Mechanism:**
- Postgres BEFORE UPDATE/DELETE/TRUNCATE triggers on `commands` table
- Trigger raises exception: `"commands table is append-only"`
- Test: `test_audit_log_immutability.py` (Postgres-only, skipped on SQLite)

**Dual-sink:**
- Primary: Postgres `commands` table (append-only)
- Secondary: Loki (via promtail scraping structured logs)
- Rationale: If attacker gains Postgres access, forensics preserved in Loki

---

### 3.6 Rate Limiting

**Status:** ⚠️ CADDY-ENFORCED (application-level fallback deferred)

**Implementation:**
- Caddy reverse proxy: 10 requests/min/IP on `/v1/enroll` endpoint
- Server accepts all valid requests; Caddy returns 429 Too Many Requests when limit exceeded
- Test: `test_rate_limit.py` (documents expected behavior, integration test manual)

**Deferred to v0.2:**
- Application-level rate limit (e.g., SlowAPI middleware) as fallback if Caddy unavailable
- Per-token rate limit (prevent single token brute-force with different IPs)

**Risk mitigation:**
- Enrollment tokens are 256-bit random (not guessable)
- Single-use tokens (replay attack mitigated)
- 24h TTL (time window limited)

---

### 3.7 Security Headers

**Status:** ✅ IMPLEMENTED

**Headers added (all responses):**
- `Strict-Transport-Security: max-age=31536000; includeSubDomains` (HSTS)
- `X-Content-Type-Options: nosniff` (MIME sniffing protection)
- `X-Frame-Options: DENY` (clickjacking protection)
- `Referrer-Policy: no-referrer` (privacy)
- `Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; ...`
  - `'unsafe-inline'` required for HTMX (eval-less) and uPlot charting
  - `frame-ancestors 'none'` prevents embedding

**Validated:** Manual testing with curl + Chrome DevTools Security tab

---

### 3.8 Code Signing

**Status:** ⚠️ DEFERRED TO v0.2.0

**Current state:**
- Cosign keyless OIDC signing implemented (GitHub Actions OIDC identity)
- Release artifacts signed: `rp-linux-x64.sig`, `rp-macos-x64.sig`, etc.
- Verification: `cosign verify-blob --bundle <file>.sig --certificate-identity-regexp ...`

**Missing:**
- Windows Authenticode EV code signing (~$300/year DigiCert/Sectigo)
- macOS notarization (Apple Developer Program $99/year)
- Auto-verification in install scripts (deferred to v0.2)

**Rationale for deferral:**
- Budget constraint (EV cert requires business verification)
- Pre-release scope (v0.1.0 homelab + family only, trusted distribution)
- Mitigation: SHA256 checksums published, manual verification documented

2. **Semgrep + Bandit** — security rulesets in CI (p/security-audit, p/owasp-top-ten)
3. **Safety dependency scan** — weekly Dependabot + CI check

6. **JWT rotation procedure** — `scripts/rotate-jwt-secret.sh` (yearly cadence)
7. **Cosign signing** — keyless OIDC for all release binaries
8. **Defense-in-depth enforcement** — local-approval flags + Telegram approvals for destructive ops

## 5. Outstanding Risks

### PRE-3: Manual configuration required (enrollment tokens)
**Impact:** MEDIUM  
**Likelihood:** HIGH  
**Description:** Admin must manually generate and distribute enrollment tokens. Vulnerable to social engineering (phishing for tokens) or token leak in insecure channels (email, SMS).  
**Mitigation:** F7 implements magic-link enrollment with short-lived links (1-hour TTL, HMAC-signed). Reduces attack window.

### PRE-4: Local-approval bypass via agent compromise
**Impact:** HIGH  
**Likelihood:** LOW  
**Description:** If attacker gains root access to enrolled host, can modify `/etc/rp/allow-remote-exec` flag to enable destructive ops. Defense-in-depth degraded to server-only enforcement.  
**Mitigation:** Root access = game over by design. Monitoring: audit log shows all command executions, Loki alerts on destructive ops in prod/iarq groups.

### SEC-1: Windows code signing deferred
**Impact:** MEDIUM  
**Likelihood:** LOW (pre-release scope)  
**Description:** Windows binaries not Authenticode-signed. Users see "Unknown publisher" warning. Increases risk of supply-chain attack (MITM substitution).  
**Mitigation:** SHA256 checksums published, manual verification documented. Target v0.2.0 (EV cert budget approval).

### SEC-2: Rate limit application-level fallback missing
**Impact:** LOW  
**Likelihood:** LOW  
**Description:** Rate limiting only enforced at Caddy layer. If Caddy misconfigured or bypassed, enrollment endpoint vulnerable to brute-force token guessing.  
**Mitigation:** 256-bit token entropy = 2^256 guesses required (infeasible). Single-use tokens mitigate replay. Target v0.2.0 for SlowAPI middleware.
